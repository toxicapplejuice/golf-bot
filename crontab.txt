# Monday 7:40 PM CT — main multi-account release bot.
#
# WHY 7:40 and not 7:51 (changed 2026-07-27): slot quality is a pure function
# of how fast the first booking lands after the 8:00 PM release. From
# history.json:
#     first booking 8:01-8:02 PM  ->  8:00-8:40 AM tee times
#     first booking 8:04 PM       ->  10:30 AM
#     first booking 8:06 PM       ->  11:31 AM
#     first booking 8:07 PM       ->  1:51 PM   (2026-07-27, nothing usable)
# The gate is Queue-it. On 2026-07-27 the accounts entered the waiting room
# at ~7:52 and were not released until ~8:06:30 — waits of 863/974/984s — so
# they started searching six minutes after the board opened and the whole
# morning was gone. Grant entered the queue earliest and also exited earliest,
# which is FIFO-shaped, so arriving earlier should mean leaving earlier.
# 7:40 clears a ~15 min queue before 8:00 with margin, restoring the June
# pattern (authenticated and idle BEFORE release) that produced 8:00 AM slots.
# multi_bot.py now logs each account's queue wait and archives the logs to
# logs/runs/, so next Monday can confirm or refute this.
#
# CONFIRMED 2026-09-07: it worked. All three accounts logged in at 19:40:28
# and hit ZERO Queue-it ("no queue hit" for michael/grant/christian) — idle
# and authenticated before the board opened. KEEP 7:40; do not move it back.
#
# Do not move it EARLIER either, absent new evidence. The queue is already
# fully cleared at 7:40, so an earlier launch buys nothing and only lengthens
# the idle-session window before release.
#
# 9/07 also proved the launch minute is no longer coupled to booking time.
# The --max-time budget used to count from LAUNCH, so 7:40 + 1800s killed
# every account at 20:11 — 20 of the 30 minutes were the pre-release sleep,
# leaving ~11 real booking minutes, and Sunday's afternoon pass never ran
# (Sunday finished 0/2 for that reason, not for lack of inventory). Since
# commit f41b265 the budget starts at the 8:00 RELEASE, so this line now
# yields a full 8:00-8:30 PM booking window.
#
# The remaining release-night gate is WebTrac's own responsiveness: on 9/07
# it served no pages for ~6 minutes after release (89 nav timeouts across the
# three accounts), which ate the entire morning/4p pass. That is handled in
# bot.py by rush mode failing fast and rotating courses, not by this schedule.
40 19 * * 1 > /Users/michaelhsu/golf-bot/multi_bot.log && /usr/bin/python3 -u /Users/michaelhsu/golf-bot/multi_bot.py >> /Users/michaelhsu/golf-bot/multi_bot.log 2>&1
